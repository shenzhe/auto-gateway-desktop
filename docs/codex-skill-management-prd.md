## 1. 执行摘要

- 在现有工作区导航中新增“技能管理”，点击后在右侧主工作区打开完整的 Codex 技能中心。
- MVP 面向使用 AUTO Gateway Desktop 管理 Codex 的个人用户，完成本机技能的查看、安装、启停、分类、导入和导出闭环。
- 分类采用“一个主分类 + 多个标签”；分类元数据由 AUTO Gateway 单独维护，不修改标准 `SKILL.md`。
- 团队技能库、权限、审核、在线版本管理和自动分发放在第二阶段，避免 MVP 依赖尚未定义的组织后台。
- 首要未决事项是确认不同 Codex 版本中真正阻止技能加载的禁用机制，以及禁用对当前会话和新会话的生效时机。

## 2. 背景与问题

AUTO Gateway Desktop 已经可以完成 Codex 安装、账号连接、网关配置、配置恢复和版本检查，但用户仍需手动进入本地目录管理 Skills。随着技能数量增加，用户难以判断：

- 当前有哪些技能可用，以及技能来自哪里；
- 某个技能是否已启用、是否存在冲突或是否需要更新；
- 如何安全安装、停用或移除技能；
- 如何按照工作类型管理大量技能；
- 如何将验证有效的技能交付给其他用户或团队。

如果继续依赖文件系统手工操作，容易产生重复技能、错误覆盖、不可恢复删除、来源不明和危险脚本误安装等问题，也无法形成后续团队分发和治理能力。

受影响用户主要是：已完成 AUTO Gateway 和 Codex 配置、会安装或使用多个 Skills 的个人用户，以及未来需要统一分发技能的团队管理员。

## 3. 假设

| 假设 | 类型 | 说明 |
| --- | --- | --- |
| “在右侧加入”指在左侧导航增加入口，在右侧工作区展示技能页面 | Inferred | 与现有桌面端导航结构一致 |
| MVP 优先管理当前用户的全局 Codex Skills | Inferred | 项目级 Skills 需要项目选择和作用域模型 |
| 用户需要先完成 Codex 安装，才能执行安装和启停 | Inferred | 未安装时仍可浏览页面，但操作受限 |
| 分类信息由 AUTO Gateway 管理，不写入 `SKILL.md` | Inferred | 避免破坏 Agent Skills 兼容性 |
| 团队技能库需要 AUTO Gateway 服务端支持 | Needs confirmation | 当前桌面端尚无技能仓库接口 |
| 禁用主要对新 Codex 会话生效 | Needs confirmation | 需在 Phase 0 验证动态重新加载能力 |

## 4. 目标与非目标

| 类型 | 目标或边界 | 衡量方式或理由 |
| --- | --- | --- |
| Goal | 用户可以在一个页面中查看所有检测到的全局技能 | 扫描成功后显示名称、来源、状态和异常 |
| Goal | 用户可以安全安装、启用、禁用和恢复用户拥有的技能 | 操作原子化、失败无残留、修改可回滚 |
| Goal | 用户可以通过分类和标签管理技能 | 支持单个和批量调整，筛选结果准确 |
| Goal | 用户可以用标准压缩包完成技能导入与分发 | 导出的技能包可被同版本产品重新安装 |
| Goal | 为后续团队技能库保留版本、来源、校验值和所有权模型 | MVP 数据结构可以平滑扩展 |
| Non-goal | MVP 不建设公开技能市场 | 需要审核、计费、举报、排名和生态治理 |
| Non-goal | MVP 不提供在线技能编辑器或 AI 创建技能 | 可在后续结合 skill-creator 能力实现 |
| Non-goal | MVP 不强制向组织成员安装技能 | 需要企业角色、策略和审计能力 |
| Non-goal | MVP 不承诺自动判定技能绝对安全 | 静态检查只能提供风险信号，不能替代信任判断 |
| Non-goal | MVP 不修改系统或插件缓存中的技能文件 | 这些技能应由对应来源管理 |

## 5. 用户与使用场景

| 用户或角色 | 使用环境 | 需要完成的任务 | 当前痛点 | 优先级 |
| --- | --- | --- | --- | --- |
| Codex 个人用户 | 本机已安装 Codex | 查看和整理已有技能 | 只能进入目录逐个检查 | P0 |
| Codex 个人用户 | 获得技能目录、压缩包或 Git 地址 | 安全安装技能 | 不清楚目录位置、结构和风险 | P0 |
| 高级用户 | 技能较多或存在重复版本 | 启停、分类、更新、回滚 | 容易覆盖本地修改或产生名称冲突 | P0 |
| 技能作者 | 需要向其他人交付技能 | 导出标准技能包 | 缺少一致的打包和校验流程 | P1 |
| 团队管理员 | 组织内复用标准工作流 | 发布、审核和分配技能 | 缺少统一目录、权限和审计 | P2 |

## 6. 产品范围

### 6.1 MVP

- 检测并展示当前用户的全局 Codex Skills。
- 区分用户、系统、插件、外部目录和 AUTO Gateway 等来源。
- 搜索、筛选、排序和技能详情。
- 主分类、自定义分类、标签和批量分类。
- 从本地目录、标准压缩包和公开 HTTPS Git 地址安装技能。
- 对用户拥有的技能执行可恢复启用、禁用、替换和移除。
- 安装前结构校验、安全检查、风险预览和冲突处理。
- 导入和导出兼容 Agent Skills 结构的技能包。
- 中英文、深浅色主题、键盘操作和响应式布局。

### 6.2 后续范围

- AUTO Skill Library 在线技能库。
- 团队发布、分享链接、版本更新和访问范围。
- 发布审核、可信发布者、签名和完整审计。
- 项目级 Skills 及全局/项目作用域切换。
- 在线编辑器、创建向导和 AI 辅助技能生成。
- 管理员推荐安装、自动安装和强制启用策略。
- 使用统计、技能调用分析和质量评价。

### 6.3 明确排除

- 未经用户确认执行技能附带的脚本。
- 静默覆盖本地修改。
- 直接删除系统、插件或外部只读目录中的技能。
- 在无法真正阻止 Codex 加载时，仅修改界面状态并声称技能已禁用。

## 7. 信息架构与页面设计

### 7.1 全局导航

在现有工作区左侧导航增加“技能管理”：

- 首页
- Codex 配置
- 技能管理
- 用户控制台

技能管理点击后在右侧主工作区打开独立页面，不增加永久占宽的第三栏。

### 7.2 技能管理页签

| 页签 | 功能 | 发布阶段 |
| --- | --- | --- |
| 已安装 | 管理本机技能、状态、分类和更新 | MVP |
| 技能库 | 浏览官方、团队或推荐技能 | Phase 2 |
| 我的分发 | 管理导出、分享、发布和版本 | Phase 2 |

### 7.3 页面结构

1. 顶部操作区：搜索、重新扫描、安装技能、分发技能。
2. 状态概览：技能总数、已启用、已禁用、可更新、异常。
3. 筛选区：分类、标签、来源、状态、风险和更新时间。
4. 技能列表：名称、描述、分类、来源、版本、状态和快捷操作。
5. 详情抽屉：完整描述、安装位置、文件、风险、校验值和历史。
6. 多选工具栏：批量分类、启停、导出或移除。

在窄窗口下，详情抽屉切换为独立详情页；筛选器折叠为弹出面板。

## 8. 分类模型

采用“一个主分类 + 多个标签”，不在 MVP 引入无限层级目录。

### 8.1 预设主分类

- 开发与工程
- 设计与创意
- 数据与文档
- Web 与营销
- 安全与质量
- 商务与协作
- 自动化与媒体
- 未分类

### 8.2 分类能力

- 新建、重命名、排序和归档自定义分类。
- 单个或批量设置主分类。
- 为技能添加多个自由标签。
- 自动推荐首次分类，但用户修改后不再自动覆盖。
- 删除分类时，要求迁移到其他分类或回到“未分类”。
- 分类和标签保存在 AUTO Gateway 的管理数据中，不写入标准 `SKILL.md`。

### 8.3 独立维度

来源不是业务分类，应单独筛选：

- 用户安装
- 系统内置
- AUTO Gateway
- 插件提供
- 外部目录
- 团队分发

## 9. 技能状态模型

| 状态 | 含义 | 用户可执行操作 |
| --- | --- | --- |
| 已启用 | Codex 可在新会话中发现并使用 | 禁用、导出、更新 |
| 已禁用 | 技能已从可发现范围安全移出或被正式配置禁用 | 启用、导出、移除 |
| 等待重新加载 | 文件状态已修改，但当前 Codex 会话可能仍持有旧状态 | 打开新会话、重新打开 Codex |
| 可更新 | 来源存在更高版本 | 查看变更、更新、忽略版本 |
| 安装中 | 正在下载、校验或写入 | 取消（安全阶段允许时） |
| 校验失败 | 技能结构或内容未通过检查 | 查看原因、重新选择来源 |
| 来源不可用 | 原始目录、Git 地址或注册表不可访问 | 重试、移除来源关联 |
| 受来源管理 | 系统或插件拥有，当前页面不能安全修改 | 打开对应来源管理入口 |

## 10. 用户流程

### 10.1 首次进入与扫描

1. 用户从左侧导航进入“技能管理”。
2. 页面展示扫描中骨架屏和已完成目录的渐进结果。
3. 系统识别技能来源、所有权、状态和异常。
4. 扫描完成后显示概览与技能列表。
5. 如果未发现技能，展示空状态，并提供“安装技能”和“打开帮助”。
6. 如果部分目录失败，保留其他结果，并在顶部显示可展开的部分失败提示。
7. 如果 Codex 未安装，页面仍可打开，但安装和启停操作不可用，并引导完成 Codex 安装。

### 10.2 安装技能

1. 用户点击“安装技能”。
2. 选择本地目录、压缩包，或输入公开 HTTPS Git 地址。
3. 系统将内容加载到临时目录，不直接写入 Codex 技能目录。
4. 校验 `SKILL.md`、名称、元数据、文件数量、文件大小和路径安全性。
5. 展示技能名称、描述、来源、脚本、资源、风险、目标位置和冲突。
6. 用户确认安装；如果存在同名技能，只提供“替换”或“取消”。
7. 替换前自动备份，随后原子写入用户技能目录。
8. 系统重新扫描并显示安装结果。
9. 如果需要新会话才能生效，状态显示“等待重新加载”。
10. 任一步骤失败时，不留下半安装目录，并给出可操作的错误信息。

### 10.3 禁用与启用

1. 用户切换技能状态。
2. 系统检查技能所有权和当前 Codex 兼容能力。
3. 可管理技能执行正式禁用配置，或迁移到 AUTO Gateway 管理的停用目录。
4. 操作成功后更新状态，并说明生效时机。
5. 操作失败时恢复原状态，不出现界面和文件系统状态不一致。
6. 启用时恢复原路径；如果目标位置已存在，要求用户先解决冲突。
7. 系统或插件技能无法安全修改时，显示“受来源管理”，不提供虚假的开关。

### 10.4 导出与分发

1. 用户选择一个用户拥有的技能并点击“分发”。
2. 系统再次验证技能结构，并提醒本地绝对路径、密钥或敏感文件风险。
3. 用户填写版本、作者和兼容性说明。
4. MVP 将技能导出为标准结构压缩包，并生成 SHA-256 校验值。
5. 用户可以保存文件或复制安装说明。
6. Phase 2 可进一步选择访问范围并发布到 AUTO Skill Library。

## 11. 功能需求

| ID | 需求 | 优先级 | 理由 | 验收标准 |
| --- | --- | --- | --- | --- |
| SK-01 | 扫描 Codex 全局技能 | Must | 所有后续能力依赖准确资产清单 | 打开页面后完成扫描；单个来源失败不影响其他结果；结果包含名称、描述、路径、来源、所有权和状态 |
| SK-02 | 搜索、筛选和排序 | Must | 技能数量增长后需要快速定位 | 可按名称和描述搜索；可组合筛选分类、标签、来源和状态；清空筛选恢复完整列表 |
| SK-03 | 管理分类和标签 | Must | 满足分类管理需求 | 可创建、重命名、排序、归档分类；可单个或批量调整；删除分类必须迁移其技能或置为未分类 |
| SK-04 | 从本地目录或压缩包安装 | Must | 覆盖最可靠的离线安装场景 | 安装前完成结构和路径校验；确认后原子写入；失败无残留；成功后列表立即可见 |
| SK-05 | 从公开 HTTPS Git 地址安装 | Must | 支持常见远程分发 | 仅接受 HTTPS；网络失败可重试；下载后复用相同安全预览和安装流程 |
| SK-06 | 启用和禁用用户技能 | Must | 用户明确要求控制技能状态 | 状态变更真正影响 Codex 的后续发现；操作可恢复；失败保持原状态；生效时机可见 |
| SK-07 | 展示技能详情和风险 | Must | 用户需要理解将安装或启用的内容 | 详情包含描述、来源、版本、路径、文件清单、脚本、校验结果、安装时间和风险信息 |
| SK-08 | 处理重复和版本冲突 | Must | 防止隐式覆盖和触发冲突 | 同名或同目标技能不得静默安装；替换前自动备份；用户可以取消且不产生变更 |
| SK-09 | 导入和导出标准技能包 | Must | MVP 需要形成可用的分发闭环 | 导出包保持标准目录结构并带校验值；由本产品重新导入后内容一致；不写入本机绝对路径 |
| SK-10 | 移除和恢复用户技能 | Should | 完整管理生命周期 | 只允许移除用户技能；默认进入可恢复区；恢复时校验目标冲突；系统技能不可删除 |
| SK-11 | 检查和安装更新 | Should | 降低技能过期和手工替换成本 | 有明确来源和版本时可检查更新；更新前显示版本与变更；失败自动恢复旧版本 |
| SK-12 | 批量管理 | Could | 提高大量技能的管理效率 | 多选后可批量分类、启停、导出或移除；不可执行项提前显示原因 |
| SK-13 | 团队技能库 | Won't（MVP） | 依赖服务端、权限和审核 | Phase 2 支持发布、版本、访问范围、撤回、回滚和审计 |

## 12. 非功能需求

| 类别 | 需求 | 验收标准 |
| --- | --- | --- |
| 性能 | 大量技能下仍能快速进入页面 | 500 个技能的本机扫描 P95 不超过 2 秒；列表筛选反馈不超过 100 毫秒 |
| 可靠性 | 所有写操作可恢复且不产生半成品 | 使用临时目录、原子替换和备份；模拟失败后原技能保持可用 |
| 安全 | 防止路径穿越、危险符号链接和无提示脚本 | 压缩包不能写出目标目录；不跟随指向技能目录之外的链接；安装前列出脚本和可执行文件 |
| 隐私 | 默认不上传技能正文或本地路径 | 分析事件不包含说明正文、脚本内容、文件内容和完整绝对路径 |
| 兼容性 | 支持目标 Codex 版本和 Windows/macOS 路径差异 | Phase 0 建立兼容矩阵；不支持的能力显示明确限制，不执行近似操作 |
| 可访问性 | 键盘和辅助技术可以完成核心流程 | 所有操作可通过键盘完成；开关有可读标签；状态不只依赖颜色 |
| 本地化 | 与现有桌面端语言能力一致 | 所有用户可见文案提供中文和英文；源代码标识符及开发者错误使用英文 |
| 可观测性 | 能定位扫描、安装和状态操作失败 | 记录匿名错误类别、来源类型、阶段和耗时；不记录技能内容和敏感路径 |
| 数据保留 | 备份和停用数据不会无限增长 | 提供保留上限或清理策略；清理前提示，系统技能永不纳入清理 |

## 13. UX 与内容要求

### 13.1 页面状态

- Loading：使用骨架屏，渐进展示已完成的来源。
- Empty：说明尚未安装用户技能，突出“安装技能”。
- Partial：展示可用结果，并提示哪些来源扫描失败。
- Error：说明失败阶段、可能原因和下一步操作。
- Conflict：展示当前版本与待安装版本，不默认选择替换。
- Success：明确安装位置、当前状态和是否需要新会话。
- Pending reload：持续显示，直到重新扫描确认或用户开始新会话。
- Read-only：系统或插件技能显示来源管理说明。

### 13.2 关键文案原则

- “禁用”必须意味着 Codex 后续不会发现该技能。
- 无法验证时使用“状态未知”，不显示成功状态。
- 风险提示必须解释具体文件或行为，不使用泛化的“可能不安全”。
- “扫描通过”应写为“未发现已知结构风险”，避免安全保证。
- 所有失败信息提供重试、查看详情、取消或恢复中的至少一个动作。

## 14. 数据模型建议

### 14.1 SkillRecord

| 字段 | 说明 |
| --- | --- |
| id | AUTO Gateway 稳定标识，不仅依赖显示名称 |
| name | 从 `SKILL.md` 读取的技能名称 |
| description | 技能说明 |
| sourceType | user、system、plugin、external、autogateway、team |
| sourceUri | 来源引用；界面展示时需要脱敏 |
| installPath | 当前安装路径，仅保存在本机 |
| scope | global；未来扩展 project |
| ownership | user-managed、source-managed、read-only |
| status | enabled、disabled、pending-reload、error 等 |

## 15. 数据与分析

### 15.1 建议事件

- `skill_manager_opened`
- `skill_scan_completed`
- `skill_install_started`
- `skill_install_completed`
- `skill_install_failed`
- `skill_status_changed`
- `skill_category_changed`
- `skill_export_completed`
- `skill_update_completed`
- `skill_recovery_completed`

事件只允许包含来源类型、技能数量、错误类别、耗时和结果，不包含技能名称、正文、脚本、文件内容或完整本地路径。

### 15.2 成功指标

| 指标 | 定义 | 基线 | MVP 目标 | 采集方式 |
| --- | --- | --- | --- | --- |
| 扫描成功率 | 无整体阻断的扫描次数 / 总扫描次数 | 无 | ≥99% | `skill_scan_completed` |
| 安装成功率 | 安装完成次数 / 安装开始次数 | 无 | ≥95% | 安装开始与结果事件 |
| 启停成功率 | 成功状态变更 / 状态变更请求 | 无 | ≥99% | `skill_status_changed` |
| 扫描性能 | 500 个技能扫描耗时 P95 | 无 | ≤2 秒 | 扫描耗时 |
| 安装残留率 | 失败安装后存在半成品的次数 | 无 | 0 | 自动检查和 QA |
| 操作恢复率 | 替换、更新或移除后可成功恢复的比例 | 无 | 100% | 恢复事件和测试 |
| 七日再次访问率 | 首次进入后七日内再次访问的用户比例 | 无 | ≥30% | 页面访问事件 |
| 导出再安装率 | 导出包后来被成功导入的比例 | 无 | ≥25% | 匿名包标识关联 |

### 15.3 护栏指标

- 安装后 Codex 启动失败率不得上升。
- 技能操作引起的配置恢复请求不得持续上升。
- 不得出现系统或插件技能被误删除事件。
- 隐私日志审查不得发现技能正文或绝对路径。

## 16. 安全与权限

- 压缩包解压前检查路径穿越和绝对路径。
- 不跟随指向目标技能目录之外的符号链接。
- 对包大小、文件数和单文件大小设置限制。
- 公开远程地址仅允许 HTTPS，并限制重定向目标。
- 安装前展示脚本、可执行文件和异常文件类型。
- 替换、更新和移除必须先创建可验证备份。
- 用户只能修改自己拥有或 AUTO Gateway 明确管理的技能。
- 系统、插件和外部只读技能显示来源，并由对应来源管理。
- 团队分发必须保存发布者、版本、校验值、访问范围和审计记录。
- 安全扫描结果不得被描述为绝对安全保证。

## 17. 依赖与约束

| 类型 | 依赖或约束 |
| --- | --- |
| Codex 兼容性 | 需要确认技能发现目录、优先级、禁用机制和动态重新加载能力 |
| 桌面端后端 | 需要新增独立的技能扫描、校验、安装、启停、备份和恢复模块 |
| 前端架构 | 当前工作区导航需要从固定首页扩展为可切换的工作区视图 |
| 跨平台 | Windows 和 macOS 的路径、文件权限、符号链接和文件锁行为不同 |
| 数据存储 | 需要保存分类、标签、停用映射、来源、校验值和备份索引 |
| 网络 | Git 安装和 Phase 2 技能库需要超时、代理、离线及重试策略 |
| 设计 | 需要桌面宽屏、980px 以下和 700px 以下三种布局状态 |
| 本地化 | 新增文案必须进入现有中英文资源体系 |
| 服务端 | Phase 2 需要技能包存储、元数据、权限、审核、分享和版本接口 |

## 18. 发布计划

### Phase 0：技术验证（3–5 个工作日）

- 确认目标 Codex 版本的技能发现目录和优先级。
- 验证正式禁用配置或接口，以及对当前/新会话的生效时机。
- 验证用户、系统、插件和外部技能的所有权边界。
- 验证 macOS 和 Windows 的目录、权限、符号链接和原子移动行为。
- 输出兼容矩阵和不可支持能力列表。

退出条件：能够可靠判断某个技能是否可管理，以及一次启停是否真正影响 Codex 的后续发现。

### Phase 1：本机技能中心（2–3 周）

- 新增导航与技能管理页面。
- 实现扫描、列表、详情、搜索和筛选。
- 实现分类、标签和批量分类。
- 实现本地目录、压缩包和公开 Git 安装。
- 实现用户技能启停、备份、移除和恢复。
- 实现标准技能包导入和导出。
- 完成中英文、深浅色、键盘操作和响应式适配。

发布策略：使用功能开关，先向内部测试用户开放，再逐步扩大到 10%、50% 和 100%。

回滚条件：发现系统技能被修改、失败操作无法恢复、Codex 启动失败率显著上升，或扫描导致持续性能问题。

### Phase 2：团队技能分发（3–4 周）

- 建设 AUTO Skill Library 服务端。
- 支持草稿、扫描、审核、发布、弃用和撤回。
- 支持个人、指定成员、团队、组织和公开访问范围。
- 支持版本、更新通知、分享链接、回滚和所有者转移。
- 支持发布者与管理员审计记录。

### Phase 3：企业治理

- 角色权限和组织策略。
- 推荐安装、自动安装和强制安装。
- 签名包、可信发布者和组织白名单。
- 组织分类模板和项目级技能策略。
- 使用分析、合规日志和数据保留设置。
